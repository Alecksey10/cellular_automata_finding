# AGENTS.md — что прочитать перед работой

Этот файл — карта проекта для ИИ-агента. Сначала прочитайте его целиком,
затем откройте файлы из нужного раздела. Не меняйте то, что помечено
`DO_NOT_TOUCH_*`, и не редактируйте сгенерированный `try_3_code/site/`
вручную.

## Что это за проект

`try_3_code` — движок перебора клеточных автоматов на Python + numba:
эксперимент описывается декларативно (оси, модули, фазы, фильтры),
конфиги перебираются параллельно, успешные конфиги сохраняются в
`successes.jsonl`, а кадры не хранятся — автомат воспроизводится из
конфига и `seed`.

Поверх движка есть две галереи:

* `python -m sweep view` — локальный сервер, кадры считает Python;
* `python -m sweep export` — статический каталог `site/`, где те же автоматы
  считаются в браузере на JavaScript, без Python и API.

Рабочий каталог по умолчанию: `try_3_code/`. Пакет не устанавливается,
запускайте команды из этой папки.

## Порядок чтения

### 1. Постановка и обзор

1. `REQUIREMENTS_BY_HUMAN.md` — исходные требования: интерфейсы,
   топологии, состояния, фильтры, сериализация, ЖЦ отбора.
2. `README.md` в корне — идея и ссылки на видео.
3. `try_3_code/README.md` — как реально устроен движок, эксперименты,
   галереи, форматы прогонов. Это главный практический документ.

### 2. Ядро движка (Python)

Читайте в таком порядке:

1. `sweep/experiment.py` — декларация эксперимента: `select`, `iterate`,
   `phase`, оси, `iter_configs`.
2. `sweep/interfaces.py` и `sweep/module.py` — `Capability`/`Requirement`,
   роли модулей (`DATA`, `RANDOMIZER`, `NEIGHBORHOOD`, `RULE`, `FILTER`).
3. `sweep/assembly.py` — проверка совместимости и сборка рантайма.
4. `sweep/runtime.py` — один тест: инициализация, фазы, метрики, фильтры,
   остановка.
5. `sweep/space.py`, `sweep/domains.py`, `sweep/handles.py` — оси, зависимые
   диапазоны, ограничения.
6. `sweep/storage.py`, `sweep/replay.py` — формат `successes.jsonl` и
   повторная сборка автомата из конфига.
7. `sweep/cli.py` — команды `space`, `modules`, `run`, `show`, `view`,
   `export`, `viz`, `live`, `rule`, `profile`.

### 3. Web-сборка (если задача про браузер)

1. `sweep/visualize/build.py` — что попадает в `site/`, как упаковываются
   сетки и собирается `assets/rules.js`.
2. `sweep/visualize/web/README.md` — **контракт браузерного модуля**,
   helpers, `Runner` и универсальные контролы. Обязательно к прочтению
   перед добавлением нового эксперимента в web.
3. `sweep/visualize/web/engine.js` — сетки, ГПСЧ, палитра, окрестности,
   общие правила `maze`/`omega5`.
4. `sweep/visualize/web/runtime.js` — реестр экспериментов и `Runner`
   (размер, итерации, скорость, цикл).
5. `sweep/visualize/web/gallery.js` и `page.html` — DOM, карточки, контролы.
6. `sweep/visualize/page.py`, `server.py`, `engine.py`, `png.py` — серверная
   галерея; она не использует `web/runtime.js`.

### 4. Эксперименты

Каждый эксперимент — отдельная папка в `sweep/experiments/<имя>/`:

* `__init__.py` — `build()`: оси, модули, фазы;
* `rule.py` (или `step.py`) — numba-итерация;
* `filters.py` — фильтры;
* `visualizer.py` — цвета, легенда, паспорт правила;
* `web.js` — браузерный модуль (если эксперимент должен попасть в `site/`).

Начинайте с `life`, затем смотрите `maze`/`maze9` (общее ядро), `langton`
(дополнительные поля карточки), `omega5` (формальный паспорт правила),
`omega5_dense` (профиль долей), `rings_rot` (BigInt-детерминизм).

## Команды

```bash
cd try_3_code

# зависимости: Python >= 3.11, numpy, numba
../.venv/bin/python -m sweep --help

# тесты (быстрые, без pytest)
../.venv/bin/python -m unittest discover -s tests -v

# перебор
../.venv/bin/python -m sweep run -e life --strategy random --limit 200 \
    --mode process --workers 4 --out runs/life

# локальная галерея (кадры считает Python)
../.venv/bin/python -m sweep view --runs runs --port 8000

# статическая галерея (кадры считает браузер)
../.venv/bin/python -m sweep export --runs runs --out site

# точечная проверка web-сборки
../.venv/bin/python -m sweep export --run-dir runs/maze --out /tmp/site
node --check site/assets/rules.js
node --check site/assets/gallery.js
```

## Инварианты, которые нельзя ломать

* Конфиг — только скаляры и `seed`; массивы, numba-объекты и замыкания
  создаются заново при сборке.
* `successes.jsonl` — самодостаточный рецепт: по `config` + `seed` автомат
  воспроизводится. Не добавляйте в него несериализуемые поля.
* Кадры не пишутся на диск; `view`, `viz`, `live` и `export` пересобирают
  их из конфига.
* Несовместимые пары «данные × правило» отсекаются до итераций через
  `Capability`/`Requirement`, а не строковыми проверками.
* Новый эксперимент регистрируется в `sweep/experiments/__init__.py`.
* Для попадания в статическую галерею нужен `web.js`; без него сборка
  честно пишет «пропущен».
* Статическая сборка не должна делать запросов к серверу: все данные лежат
  в `index.html`, весь код — в `assets/`.

## Если задача про новый эксперимент

Чек-лист:

1. Папка `sweep/experiments/<имя>/`, `build()` возвращает свежий
   `Experiment` при каждом вызове.
2. Итерация — отдельная numba-функция, без глобального состояния.
3. Все параметры объявлены осями (`e.range`, `e.choice`, `e.value`) и
   попадают в конфиг.
4. Фильтры — отдельные модули с `requires`, а не код внутри итерации.
5. Визуализатор: `state_color`, `legend`, `rule_info`; он нужен и
   серверной, и статической галерее.
6. `web.js` — только `create`/`step` + helpers; размер, скорость, цикл и
   число итераций не реализуйте в модуле, это делает `Runner`.
7. Если нужны дополнительные поля карточки или регуляторы галереи, используйте
   необязательные хуки `web_card_details` и `web_meta_parameters` в пакете
   эксперимента, а не правки в `build.py`/`replay.py`.
8. Тест в `tests/test_sweep.py`: сборка, детерминизм, `module_path`.
9. `python -m sweep export --run-dir runs/<имя> --out /tmp/site` и
   открыть страницу.

## Если задача про web-интерфейс

* Универсальные контролы уже есть у каждой карточки: `▶/⏸`, `↺`, `цикл`,
  `размер`, `итер.`, `итер/с`. Меняйте их в `gallery.js`/`page.html`, а
  поведение — в `Runner` (`runtime.js`).
* «Итер/с» — это число шагов автомата в секунду, а не FPS отрисовки.
  При значении `1` шаг должен происходить примерно раз в секунду.
* «Размер» меняет инициализирующую сетку (ближайший сосед) и пересоздаёт
  состояние; он не обязан совпадать с Python-прогоном, но должен быть
  воспроизводимым в браузере.
* «Итерации» — цель обзора. Цикл после неё начинает состояние заново.
* Анимация должна идти только для видимых карточек (IntersectionObserver).
* После правок JS обязательно проверяйте `node --check` собранных файлов.

## Что не трогать

* `DO_NOT_TOUCH_try_2_code/`, `DO_NOT_TOUCH_try_2_plans/` — архив прошлых
  попыток.
* `try_3_code/runs/` — данные прогонов. Их можно читать и создавать новые,
  но не переписывайте существующие успехи вручную.
* `try_3_code/site/` — сгенерированный каталог. Меняйте исходники в
  `sweep/visualize/`, затем пересобирайте.
* `try_3_code/viz/`, `static/*.png`, `static/*.mp4` — артефакты и медиа.

## Стиль работы

* Документация и комментарии — по-русски, как в проекте; имена кода —
  по-английски.
* Сначала прочитайте существующий модуль-аналог, потом пишите новый.
* Маленькие изменения предпочтительнее переписывания: сохраняйте стиль
  `sweep/`.
* После Python-правок запускайте `unittest`; после web-правок — `export`
  и `node --check`.
* Если добавляете новое правило или контрол — обновите этот файл и
  `try_3_code/README.md`.
